## UC-1. Регистрация

**Описание:** Как **неавторизованный пользователь** я хочу зарегистрироваться в системе, чтобы создать свой профиль.

### Поля и правила валидации формы

Форма регистрации содержит все обязательные поля:

| Поле | Правила |
| --- | --- |
| `username` | `min=6`, `max=30`, допустимые символы: `0-9`, `A-Z`, `a-z`, `_`, `-` |
| `email` | валидный email |
| `password` | `min=6`, `max=20`, должен содержать: `0-9`, `A-Z`, `a-z`; может содержать: <code>! " # $ % & ' ( ) * + , - . / : ; < = > ? @ [ \ ] ^ _ { \| } ~</code> |
| `password confirmation` | должен совпадать с `password` |

Дополнительно форма содержит:

- Чек-бокс **«I agree to the Terms of Service and Privacy Policy»** (со ссылками на страницы Terms of Service и Privacy Policy);
- Кнопку **[ Sign Up ]**.

**Момент валидации:** валидация введённых значений происходит при потере фокуса полем (клик вне поля либо переключение на другое поле).

**Условия неактивности кнопки [ Sign Up ]:** кнопка неактивна, если:

- одно из полей не заполнено;
- одно из полей заполнено невалидными значениями;
- не установлен чек-бокс.

### Основной сценарий

| Шаг | Описание | Примечание |
| --- | --- | --- |
| 1 | Неавторизованный пользователь находится на странице Регистрации | Форма содержит поля, чек-бокс и кнопку [ Sign Up ] (см. таблицу полей выше) |
| 2 | Пользователь вводит `username`, `email`, `password`, `password confirmation` | Валидация происходит при потере фокуса полем |
| 3 | Пользователь устанавливает чек-бокс «I agree to the Terms of Service and Privacy Policy» | Может перейти на страницы Terms of Service и Privacy Policy |
| 4 | Пользователь нажимает кнопку [ Sign Up ] | Кнопка неактивна по условиям выше |
| 5 | Система отображает сообщение | Текст: `{ We have sent a link to confirm your email to ___email___ }` |
| 6 | Система отправляет ссылку для подтверждения email на введённый адрес | Ссылка активна 1 час |
| 7 | Пользователь закрывает сообщение ([ OK ] или крестик) и остаётся на странице «Sign Up» | Поля формы очищаются после отправки |
| 8 | Пользователь переходит по ссылке из письма | |
| 9 | Система перенаправляет пользователя на страницу входа | Страница содержит: `{ Congratulations! Your email has been confirmed }` и кнопку [ Sign In ] |
| 10 | Пользователь нажимает [ Sign In ] | Войти первый раз без подтверждённого email нельзя — переход по ссылке обязателен. Кнопка [ Sign In ] неактивна, если поле не заполнено и/или заполнено невалидно |
| 11 | Система перенаправляет пользователя на страницу Входа в систему | |

## UC-2. Вход в систему (Log In)

**Описание:** Как **неавторизованный пользователь** я хочу войти в систему, чтобы создать аккаунт, а также пользоваться своим аккаунтом — добавлять фотографии, оставлять комментарии.

### Поля формы

Форма входа содержит:

- `Email`;
- `Password`;
- Кнопку **[ Sign In ]**.

**Момент валидации:** валидация введённых значений происходит при потере фокуса полем (клик вне поля либо переключение на другое поле).

### Основной сценарий

| Шаг | Описание | Примечание |
| --- | --- | --- |
| 1 | Неавторизованный пользователь открывает страницу Входа | Форма содержит: Email, Password, кнопку [ Sign In ] |
| 2 | Пользователь вводит Email и Password | Валидация происходит при потере фокуса полем |
| 3 | Пользователь нажимает [ Sign In ] | |
| 4 | Система предоставляет доступ к платформе авторизованному пользователю | Система перенаправляет авторизованного пользователя на страницу аккаунта |

### Альтернативный сценарий — ввод некорректного Email и/или пароля

| Шаг | Описание | Примечание |
| --- | --- | --- |
| 1–3 | Шаги основного сценария | |
| 3.1 | Система отображает сообщение о том, что пароль и/или email введён некорректно, и оставляет пользователя на странице Входа | Текст: `{ The email must match the format example@example.com }` |
| 3.2 | Пользователь повторно вводит email и/или пароль | |
| 3–4 | Шаги основного сценария | |

## UC-5. Регистрация и вход с помощью Google или GitHub (необязательно)

**Описание:** Как **неавторизованный пользователь** я хочу зарегистрироваться в системе, чтобы создать свой профиль.

### Основной сценарий

| Шаг | Описание | Примечание |
| --- | --- | --- |
| 1 | Неавторизованный пользователь регистрируется через Google/GitHub | |
| 2 | Система генерирует username пользователю (типа «client1», «client2»…) | Т.к. при регистрации необходимо указать username, при OAuth username должен сгенерироваться |
| 3 | Система перенаправляет авторизованного пользователя на домашнюю страницу — т.е. пользователь и зарегистрировался, и вошёл в систему | Задать пароль (для входа через email и password) возможно через восстановление пароля (т.к. при входе через GitHub и Google пароль не устанавливается) |
| 4 | Система отправляет на почту письмо-уведомление об успешной регистрации в системе | |

### Альтернативный сценарий — пользователь с таким email уже есть в системе

| Шаг | Описание | Примечание |
| --- | --- | --- |
| 1 | Неавторизованный пользователь регистрируется с помощью Google или GitHub | |
| 2 | Система добавляет к пользователю в поле «providers» сервис, с помощью которого был произведён вход, и перенаправляет авторизованного пользователя на домашнюю страницу | См. подробнее схему и видео |

> Данная функциональность может быть реализована и другими способами, но в рамках учебного проекта необходимо использовать предложенное решение.
