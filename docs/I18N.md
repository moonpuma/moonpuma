# Переводы (i18n)

Как добавлять и использовать переводы в приложении. Технические детали архитектуры (роутинг,
`proxy.ts`, `[locale]`-сегмент) — в `CLAUDE.md`, раздел «Feature-Sliced Design (FSD)». Этот файл —
только про повседневную работу с текстом: где лежат строки и как их подключить в компонент.

Используется библиотека [next-intl](https://next-intl.dev). Локали: `en` (дефолтная), `ru`.
Локаль всегда есть в URL (`/en`, `/ru/sign-in`).

> **Текущий статус:** `messages/en.json` и `messages/ru.json` пока пустые — реализована только
> инфраструктура (роутинг, `Link`/`useRouter`), сам текст компонентов ещё не переведён и лежит
> захардкоженным в JSX. Ниже — как это будет делаться, когда дойдёт очередь.

## Где лежат строки

- `messages/en.json`, `messages/ru.json` — словари, ключи сгруппированы по неймспейсу
  (компонент/страница/фича), а не одним плоским списком:

  ```json
  {
    "header": {
      "logIn": "Log in",
      "signUp": "Sign up"
    }
  }
  ```

- `src/shared/i18n/request.ts` подгружает нужный файл по локали текущего запроса — руками его
  трогать не нужно, только словари.

## Как использовать перевод в компоненте

**Client Component** (`'use client'`) — хук `useTranslations`:

```tsx
import { useTranslations } from 'next-intl'

const t = useTranslations('header')
// ...
<Button>{t('logIn')}</Button>
```

**Server Component** — асинхронная версия `getTranslations`:

```tsx
import { getTranslations } from 'next-intl/server'

const t = await getTranslations('header')
```

Аргумент — неймспейс (верхнеуровневый ключ в JSON), дальше `t('logIn')` берёт вложенный ключ.

## Текст со вложенной ссылкой

Для фраз с разметкой посреди текста (как согласие с Terms/Privacy в `SignUpForm`) — не резать
строку на части в JSX, а хранить как один ключ с тегами и подставлять теги через `t.rich()`:

```json
{ "signUp": { "agreement": "I agree to the <terms>Terms of Service</terms> and <privacy>Privacy Policy</privacy>" } }
```

```tsx
t.rich('agreement', {
  terms: (chunks) => <Link href='/terms-of-service'>{chunks}</Link>,
  privacy: (chunks) => <Link href='/privacy-policy'>{chunks}</Link>,
})
```

Это и есть основная причина, почему для переводов взят next-intl, а не самописный словарь.

## Ссылки и навигация

Внутренние ссылки и `router.push`/`replace` — всегда через `@/shared/i18n/navigation`
(`Link`, `useRouter`, `usePathname`), а не голые `next/link`/`next/navigation`. Иначе переход
потеряет текущую локаль.

## Как добавить новую локаль

1. Добавить код локали в `locales` в `src/shared/i18n/routing.ts`.
2. Создать `messages/<locale>.json` (можно скопировать структуру из `en.json`).
3. Добавить флаг (`src/shared/ui/icon/icons/locale/`) и пункт в `languageOptions` в
   `src/widgets/header/Header.tsx`.

## Соглашения

- Ключи — по неймспейсу компонента/страницы, а не общий плоский список.
- Тексты сообщений — дословно из спеки в `docs/AUTH.md`, если флоу там описан.
- Не хардкодить текст в JSX, если рядом уже есть словарь для этого компонента — использовать
  `useTranslations`/`getTranslations`.
