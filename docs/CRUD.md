## 1. Добавление/редактирование/просмотр своих постов

### UC-1. Добавление поста с загрузкой фото

**Описание.** Как авторизованный пользователь я хочу добавить пост с фотографией в ленту, чтобы поделиться им со своими друзьями.

**Основной сценарий**

| Шаг | Описание | Примечание |
|---|---|---|
| 1 | Авторизованный пользователь нажимает пункт «Create» в меню | |
| 2 | Система отображает форму добавления фотографии | Форма содержит: placeholder, кнопку **[ Select from Computer ]** и опционально кнопку **[ Open draft ]** |
| 3 | Пользователь нажимает **[ Select from Computer ]** и загружает фотографию | Требования к фото: формат JPEG/PNG, размер не более 20 МБ |
| 4 | Система отображает форму с загруженной фотографией | |
| 5 | Пользователь может настроить фото | Доступно: изменение масштаба (1:1, 4:5, 16:9), приближение, загрузка до 10 фото для публикации. Интерфейс зависит от выбранной библиотеки |
| 6 | Пользователь нажимает **[ Next ]** | |
| 7 | Система отображает форму с выбором фильтров для фото (необязательно) | Интерфейс зависит от выбранной библиотеки |
| 8 | Пользователь нажимает **[ Next ]** | |
| 9 | Система отображает форму с загруженным фото и полями для заполнения | Форма содержит: фото с фильтрами (если были) и поле **Description** (макс. 500 символов, необязательное). Поле **Location** на этом этапе не реализуется |
| 10 | Пользователь заполняет **Description** и нажимает **[ Publish ]** | |
| 11 | Система сохраняет публикацию и отображает её в ленте пользователя | |

**Альтернативный сценарий №1 — возврат на предыдущий шаг**

| Шаг | Описание |
|---|---|
| 1–9 | Шаги основного сценария |
| 10 | Пользователь нажимает символ «Назад» в форме перед публикацией |
| 11 | Система возвращает пользователя на предыдущий шаг (выбор фильтра) |

**Альтернативный сценарий №2 — отмена публикации (клик вне формы)**

| Шаг | Описание | Примечание |
|---|---|---|
| 1–9 | Шаги основного сценария | |
| 10 | Пользователь кликает вне формы | |
| 11 | Система отображает сообщение | «Do you really want to close the creation of a publication? If you close everything will be deleted» |
| 12.1 | Пользователь нажимает **[ Save draft ]** (опционально) | |
| 13.1 | Система не сохраняет публикацию и возвращает пользователя на домашнюю страницу | |
| 12.2 | Пользователь нажимает **[ Discard ]** или крестик | |
| 13.2 | Система оставляет пользователя на форме публикации поста | |

**Альтернативный сценарий №3 — выход на этапе загрузки фото**

| Шаг | Описание | Примечание |
|---|---|---|
| 1–4 | Шаги основного сценария | |
| 3 | Пользователь нажимает символ «Назад» в форме | |
| 4–11 | Далее — шаги альтернативного сценария №2 (отмена публикации) | |

**Альтернативный сценарий №4 — некорректный формат/размер фото**

| Шаг | Описание | Примечание |
|---|---|---|
| 1–3 | Шаги основного сценария | |
| 3 | Пользователь получает сообщение об ошибке, закрывает модальное окно и остаётся на странице загрузки фото | «The photo must be less than 20 Mb and have JPEG or PNG format» |
| 4–11 | Шаги основного сценария | |

### UC-2. Редактирование поста

**Описание.** Как авторизованный пользователь я хочу редактировать свой ранее опубликованный пост, чтобы внести изменения.

**Основной сценарий**

| Шаг | Описание | Примечание |
|---|---|---|
| 1 | Пользователь открывает ранее созданную публикацию | |
| 2 | Система отображает публикацию вместе с описанием и комментариями | |
| 3 | Пользователь нажимает на контекстное меню (три точки) | |
| 4 | Система отображает действия **«Edit Post»** и **«Delete Post»** | |
| 5 | Пользователь нажимает **«Edit Post»** | |
| 6 | Система открывает форму редактирования | Редактировать можно только описание поста |
| 7 | Пользователь вносит изменения и нажимает **[ Save Changes ]** | |
| 8 | Система сохраняет изменения, пользователь остаётся на странице поста | |

**Альтернативный сценарий — выход без сохранения**

| Шаг | Описание | Примечание |
|---|---|---|
| 1–6 | Шаги основного сценария | |
| 7 | Пользователь нажимает крестик либо кликает за пределами формы | |
| 8 | Система отображает сообщение | «Do you really want to finish editing? If you close the changes you have made will not be saved» |
| 9 | Система не сохраняет изменения, пользователь остаётся на странице поста | |
| 10.1 | Пользователь нажимает **[ Yes ]** | |
| 11.1 | Изменения не сохраняются, пользователь остаётся на странице поста | |
| 10.2 | Пользователь нажимает **[ No ]** или крестик | |
| 11.2 | Пользователь остаётся на форме редактирования | |

> Примечание: если пользователь не внёс изменений в пост, модальное окно подтверждения не отображается.

### UC-3. Удаление поста

**Описание.** Как авторизованный пользователь я хочу удалить свой ранее опубликованный пост, чтобы другие пользователи его не видели.

**Основной сценарий**

| Шаг | Описание |
|---|---|
| 1 | Пользователь открывает ранее созданную публикацию |
| 2 | Система отображает публикацию вместе с описанием и комментариями |
| 3 | Пользователь нажимает на контекстное меню (три точки) |
| 4 | Система отображает действия **«Edit Post»** и **«Delete Post»** |
| 5 | Пользователь нажимает **«Delete Post»** |
| 6 | Система отображает подтверждающее сообщение |
| 7 | Пользователь нажимает **[ Yes ]** |
| 8 | Система удаляет публикацию, пользователь остаётся на домашней странице |

**Альтернативный сценарий — отмена удаления**

| Шаг | Описание |
|---|---|
| 1–6 | Шаги основного сценария |
| 7 | Пользователь нажимает крестик либо **[ No ]** |
| 8 | Публикация не удаляется, пользователь остаётся на странице поста |

### UC-4. Просмотр своих постов

**Описание.** Как авторизованный пользователь я хочу просмотреть все свои ранее опубликованные посты.

**Сценарий**

| Шаг | Описание | Примечание |
|---|---|---|
| 1 | Пользователь открывает свою домашнюю страницу (пункт сайдбара «My profile») | URL содержит id пользователя. Страница профиля доступна для просмотра всем без авторизации, но редактировать профиль (создавать/удалять/изменять посты и другую информацию) может только авторизованный владелец профиля |
| 2 | Система отображает публикации пользователя (последние 8 постов, от новых к старым) | Страница содержит: фото пользователя, username, About me, кнопку **[ Profile Setting ]** и посты |
| 3 | Пользователь может просмотреть больше постов через скролл | Система подгружает по 8 постов за раз |

## 2. Главная страница с постами (SSG/ISR)

### UC-1. Просмотр постов на главной странице

> ⚠️ **Важно (техническое ограничение реализации).**
> - Авторизацию пользователя (запрос `/me`) проверяем **на стороне клиента**.
> - Контент с сервера, доступный всем пользователям, должен быть отрендерен сразу (SSR/SSG).
> - Контент, зависящий от авторизации (header, сайдбар и т.д.), подгружается уже на клиенте.

**Описание.** Как авторизованный и неавторизованный пользователь, я хочу иметь возможность просматривать публичные посты на главной странице приложения, чтобы мне было легко получать доступ к интересному контенту.

**Сценарий**

| Шаг | Описание | Примечание |
|---|---|---|
| 1 | Пользователь заходит на главную страницу | — Страница доступна по адресу `/`.<br>— Отображает количество зарегистрированных пользователей и 4 последних поста.<br>— Для авторизованного пользователя — сайдбар и хедер авторизованного пользователя; для неавторизованного — кнопки **[ Log In ]** и **[ Sign Up ]**.<br>— Контент обновляется каждую минуту (альтернатива: при регистрации 5 новых пользователей или добавлении 4 новых постов).<br>Рекомендуется **SSG (ISR)**, опционально — On-Demand Revalidation |
| 2 | Сервер обрабатывает запрос на главную страницу | |
| 3 | Сервер выполняет запрос к базе данных для получения списка постов | |
| 4 | Сервер отправляет сгенерированную HTML-страницу с 4 постами | |
| 5 | Пользователь видит главную страницу с 4 постами | |
